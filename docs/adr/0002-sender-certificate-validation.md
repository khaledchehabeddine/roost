# Sender Certificate Validation

Roost checks a Sender Certificate using only the certificate and inputs the app passes in, such as the domain keys it trusts to sign certificates, revoked Identity Keys, the current time, and a grace window for recently expired certificates. Roost reads no clock of its own, because key rotation, revocation, and clock policy belong to the app, but it caps the grace window so an app can't keep an expired certificate valid indefinitely. The app can trust several domain keys at once, so a domain can rotate its signing key without invalidating certificates already in use.
