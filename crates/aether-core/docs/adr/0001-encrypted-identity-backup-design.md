# Encrypted Identity Backup Design

**Status:** Accepted

Identity backups are encrypted with XChaCha20-Poly1305 (the same AEAD chosen for messages) under a key derived from the user's passphrase via Argon2id, chosen for its memory-hard design that defeats GPU and ASIC brute-force at OWASP-baseline cost. A backup carries both the permanent identity keypair and the current discovery keypair, so importing it on another device restores the same identity and continues its discovery-epoch lineage rather than starting fresh. The backup file is self-describing — a version byte and the Argon2id parameters travel in a cleartext header that is authenticated as the AEAD's associated data, so neither the version nor a work-factor parameter can be altered without failing decryption — and the library refuses to read any backup whose Argon2id cost falls below a normative floor, blocking work-factor downgrade from old or hostile files. The passphrase is normalized to canonical Unicode form before derivation so the same characters typed on any platform produce the same key, secret material is zeroized once unneeded, and the library publishes backup-format test vectors so backups round-trip across library versions.
