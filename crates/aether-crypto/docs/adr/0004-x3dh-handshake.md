# X3DH Handshake

**Status:** Accepted

Initial session establishment uses Signal's X3DH handshake against the recipient's prekey bundle (signed pre-key plus one-time pre-keys), combining Diffie-Hellman over four inputs — identity key, ephemeral key, signed pre-key, and a one-time pre-key when available — via HKDF-SHA256 with a protocol-specific info string. X3DH is chosen because mixing the four DH outputs gives forward secrecy against compromise of any single key and lets the initiator establish a session asynchronously without the responder being online, which is essential for a messaging product where peers connect on different schedules. A one-time pre-key is consumed per handshake to maximize forward secrecy; the signed pre-key (rotated weekly) is the fallback when OPKs are exhausted, and the bundle belongs to the responder's current discovery key epoch so DK rotation invalidates the prior epoch's pre-keys, building on the Curve25519 primitives in [DR 0001](0001-cryptographic-primitive-selection.md).
